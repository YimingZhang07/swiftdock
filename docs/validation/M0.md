## 手工复现步骤

先在普通权限终端启动 `scripts/Run.ps1`，只运行一个 M0 实例。结束用托盘或面板“退出”。每组记录源应用/版本、结果、日志时间及显示器缩放。

1. 在记事本、Explorer、Chrome/Edge 前台分别按 Alt+Space；观察出现位置，直接按方向键/Enter，再按热键、Esc 或点击外部验证隐藏。另测菜单打开、管理员窗口在前台和锁屏恢复，失败时检查日志并确认无卡死/输入注入。
2. 将鼠标放到不同缩放比例、位于主屏左侧/上方的显示器，呼出窗口，检查完整位于工作区；跨屏时检查字体与位置，记录 `window.dpi`。
3. 拖动首项到末尾、尾项到首位；悬停“工作”400ms 后松到网格；再分别用 Esc、窗外松开取消，确认原组数据和捕获状态恢复。M0 暂不含让位动画/边缘自动滚动，相关最终体验在 M4 完成。
4. 勾选“保持显示以添加”，从 Explorer 拖入 exe、lnk、目录、文档和 `.url`；从 Chrome/Edge 地址栏和网页链接拖入。检查 `drop.capture` 的格式和耗时、标题缺失时域名回退；再测试拖动开始后热键呼出。按需使用离线路径验证 UI 仍响应。
5. 点击添加的各类条目，确认先隐藏再启动；应用右键“以管理员身份运行”后取消 UAC，检查 `launch.result` 中 cancelled=true。无文件关联、路径失效等应显示失败状态且可再次打开面板。
6. 端到端抽查采用能同时关联物理按键、首个可辨认画面与键盘响应的高帧率录像，或记录方法明确的输入/呈现跟踪；记录采样率和误差。没有此证据时只使用 UI 代理指标名称。

## 实现中发现的问题与取舍

- H.NotifyIcon 2.4.1 不接受任意 `DrawingImage` 作为 IconSource；实际运行发现后改用其支持的 `GeneratedIconSource`。不依赖未经验证的 WPF 图像类型转换。
- 无效 `.url` 会产生 `InvalidDataException`，已将其显式加入逐项错误处理；不让一个坏项目使有效批次全部失败。对应回归测试通过。
- 受限执行环境会拒绝热键/托盘操作（错误 5 / TryCreate failed），测试宿主 IPC 也可能超时；在正常本机会话验证成功，且不是管理员运行。保留真实限制，未添加绕过输入权限的代码。
- CLI 构建脚本关闭共享构建服务器并使用单节点，以避免执行环境的 IPC 限制；不是运行时性能优化。
- 运行脚本启动 apphost exe，确保其 asInvoker/PerMonitorV2 manifest 生效；使用仓库内 Runtime 无需系统级安装。
- M0 使用代码后置协调最小窗口原型和两个硬编码分组；M1 再加入正式配置/单实例及视图模型。没有把 M3/M4 的完整去重、占位队列、自动滚动、动画和撤销宣称为已完成。
- 日志、快照、测试结果、发布目录位于忽略的 `artifacts/`，源码、包锁及本记录进入 Git。
