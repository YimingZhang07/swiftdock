# M2–M5 实施与验证

日期：2026-10-13（America/New_York）。v0.1.0 的剩余功能已实现；自动验证通过。**真实键鼠/浏览器矩阵及全部性能目标尚未完成验收**，不将程序内控件检查替代这些证据。

| 阶段 | 实现内容 |

| M3 | FileDrop/Unicode URL/Mozilla URL/ANSI/文本解析，标题降级；后台文件检查和描述；立即显示不持久化的占位项；文件与 URL 分别去重；目标组失效/取消处理；AllowedEffects 协商和源文件保留 |
| M4 | 窗口根捕获，组内/跨组事务、重复目标拒绝、新建组并移动、标签重排；150ms 让位、120ms 飞入、根层拖影、边缘滚动；取消恢复；导入提交等待内部拖拽结束 |

## 验证方法

- `scripts/Validate.ps1 -DesktopSmoke`：锁定依赖还原、Release 构建（零警告）、50 项逻辑/资源测试、程序内 WPF 检查。
- 当前程序内检查覆盖真实图标冻结、窗口/捕获复用、预热被用户显示请求中断、排序保存、设置、编辑对话框、主题资源更新、导入去重、编辑保留 ID、删除撤销、分组视图及双进程转发。原始结果在 `artifacts/validation/smoke-result.json`。
- 自启测试仅使用 `HKCU\Software\QuickLaunch\Tests\<guid>`，随后移除测试键；未更改真正的 Run 项。
- 图标测试验证 48 DIP 的 100%/150%/200% 请求尺寸、内存复用、重建服务后的磁盘命中及损坏 PNG 恢复；程序窗口中实际提取并显示 exe/文件夹图标。
- 基准使用独立生成的 4×50 项和单组 200 项（exe、lnk、文件夹、文件、URL），每种常规指标 100 个样本。运行中不启动这些条目。
- `GetProcessMemoryInfo(PROCESS_MEMORY_COUNTERS_EX2)` 记录专用工作集，另外记录 Private Bytes、总工作集、托管堆。无主动 GC 或工作集修剪。
- 截图是 WPF RenderTargetBitmap 布局快照；渲染回调不是物理呈现完成，也不是实际热键输入的起点。

## 性能决策与限制

启动对照（10 次进程启动，文件系统缓存未清空，不是重启冷启动）：普通独立版 P50 476.20ms / P95 485.37ms；R2R 独立版 P50 445.49ms / P95 512.45ms。样本不支持稳定的尾部延迟改善，默认保持 ReadyToRun=false，保留对照开关。

预热实验发现，仅显示透明 HWND 后等待渲染回调不足以覆盖真实内容绘制。最终方案先验证窗口位于虚拟桌面外，再绘制不透明内容；用户显示请求会取消旧预热，旧回调不会隐藏用户窗口。默认仅在静默启动的空闲时段执行，正常手动启动直接显示。

一次单组 200 项的预热后首个渲染回调为 44.96ms；100 次重复显示的渲染代理 P95 4.73ms，Hide 调用 P95 3.09ms。**该运行 100 次前台确认均失败，因此完整“可见且可输入”P95 不可用，不能称作 50ms 呼出达标。** 同组切换是控制组，不当作跨组切换性能。

该样本专用工作集约 80.2 MiB，高于原计划暂定的 60MB 预算；未通过修剪工作集掩盖差异。首次渲染、长期闲置恢复及四组数据的最终结果保存在证据 JSON，后续更新本节汇总。

## 人工验证缺口

Windows computer-use 工具尝试打开记事本作为前台时返回 `Computer Use app approval timed out`，未继续操作该应用，也未使用另一条 UI 自动化路径绕过授权。真实键鼠、Chrome/Edge/Explorer OLE、混合 DPI/负坐标、UAC、跨登录会话 UI、系统主题切换通知、注销/关机及 Explorer 重启仍列为未验证。

程序内编辑对话框使用控件事件，主题测试直接更新资源；它们分别证明保存路径和资源传播，不能证明真实鼠标动作或系统设置变更已测试。UAC/重启等未实际触发，不伪造通过记录。

## 交付

`scripts/Publish.ps1` 默认生成 Windows x64 独立目录、ZIP 和 SHA-256，运行不依赖系统已安装的 .NET。`-FrameworkDependent` 和 `-ReadyToRun` 可生成对照版本。源代码、锁文件及验证记录进入 Git；SDK、缓存、测试配置和二进制在忽略的 `artifacts/` / `.tools/`。
